# Voice Input Bridge 🎙️

> **手机语音秒变电脑打字**：电脑没有麦克风也能用！把手机变成你的专属无线语音输入法（支持 **Linux** 与 **Windows**）。  
> 利用手机端极高精度的输入法（豆包、微信输入法、讯飞、Gboard 等），通过局域网秒级上屏到当前光标输入框与剪贴板。

## 🎯 它能解决你的什么需求？

如果你在使用 Linux 时遇到了以下情况，这个项目就是为你准备的：

- [x] **电脑没有外置麦克风**：台式机或特定工作站没有麦克风，不想为了偶尔语音打字额外花钱买硬件。
- [x] **Linux 缺少好用的系统级语音输入法**：目前 Linux 桌面很难找到开箱即用、识别精度高的系统级中文语音输入工具。
- [x] **电脑跑语音大模型太重太卡**：在电脑本地折腾 Whisper、FunASR 等模型既吃显存、占 CPU、风扇狂转，识别中英混杂效果还不理想。
- [x] **手机输入法语音极好用，却无法在电脑上用**：手机上的豆包输入法、微信输入法、讯飞识别率极高，能自动纠错润色，但无法直接把打出的字送进 Linux。

### 💡 核心解决思路

**让专业设备做专业的事，中间极简互联**：
- **手机端**：只负责最擅长的“语音转文字”（直接利用手机自带的成熟语音输入法，**手机端 0 安装 App，扫码即用**）；
- **电脑端**：只负责“接收文本并毫秒级上屏”（单文件轻量脚本，**不吃一分钱电脑算力**）。

## 🚀 怎么使用？

### 第一步：电脑启动（只需 1 条命令或双击）

通过终端克隆并运行交互式控制中心：

```bash
git clone https://github.com/yyxxd/voice-input.git
cd voice-input

# 🐧 Linux 用户运行:
./menu.sh

# 🪟 Windows 用户运行:
menu.bat
```

> **🖥️ 偏好图形界面直接双击？**
> - **Linux**：在文件管理器中双击 **`voice-input.desktop`** 或 `menu.sh`。
> - **Windows**：直接双击 **`menu.bat`** 即可打开中文控制面板！
首次运行时，脚本会**自动静默自检依赖**（若缺少工具会自动提示并一键安装，总大小 < 200 KB）。  
终端控制中心使用 **↑ / ↓ 选择、Enter 执行、Q 退出**，当前选项高亮显示。选择「手机连接 / 二维码」查看扫码入口。

### 第二步：手机扫码连接

1. 确保手机和电脑连接**同一 Wi-Fi**（或者同一 Tailscale / 节点小宝等虚拟组网）；
2. 手机打开系统相机、微信或浏览器“扫一扫”，扫描终端上的二维码（或直接访问显示的网址）。

---

### 第三步：日常语音打字体验

1. **光标就位**：在电脑上鼠标点击任何你想输入的地方（浏览器搜索框、聊天窗口、VS Code 或终端）。
2. **说话输入**：
   - 在手机网页的输入框内点击，唤出手机键盘；
   - **长按手机输入法的语音键说话**（可利用豆包、微信输入法等极速识别与自动润色）；
3. **一键上屏**：
   - 点击手机底部的 **「发送至电脑」**；
   - **GNOME 终端**：发送前选择「终端模式」；普通应用选择「直接上屏」。
   - 电脑音响会发出一声轻快的“嗒”提示音，**文字瞬间出现在电脑当前光标处**！
   - **极速连招**：勾选底部的 **「自动回车」**，文字上屏后电脑端自动敲下回车，在终端跑命令或聊天发消息一气呵成！
   - *（注：如果电脑当前没有聚焦在任何输入框，文字也会**完整保存在系统剪贴板中**，终端按 `Ctrl+Shift+V` 或常规软件按 `Ctrl+V` 即可粘贴，绝不丢失。）*
4. **无缝连续输入**：
   - 点击发送后，手机软键盘**绝不收起**，方便你紧接着长按语音键说下一句。

### 什么时候使用「终端模式」？

默认使用 **「直接上屏」**。文字先写入电脑剪贴板，再按当前窗口的粘贴快捷键上屏：普通应用通常使用 `Ctrl+V`，终端通常使用 `Ctrl+Shift+V`。

| 使用环境 / 场景 | 建议模式 | 当前行为 |
| :--- | :--- | :--- |
| **Hyprland、Sway** 上的常见终端与普通应用 | 直接上屏 | 通过 `hyprctl` / `swaymsg` 获取当前窗口，自动判断是否为常见终端并选择粘贴快捷键。 |
| **Windows** 上的常见独立终端与普通应用 | 直接上屏 | 根据前台窗口类名和进程名自动判断是否为常见终端并选择粘贴快捷键。 |
| **GNOME Wayland** 上的浏览器、编辑器、聊天软件等普通输入框 | 直接上屏 | 使用 Mutter 键盘接口模拟 `Ctrl+V`。 |
| **GNOME Wayland** 上的终端 | 终端模式 | 当前没有 GNOME 窗口类型识别，需手动指定 `Ctrl+Shift+V`。 |
| 其他 Linux 桌面、未识别的终端，或编辑器内嵌终端 | 终端模式（当该输入区域使用 `Ctrl+Shift+V` 粘贴时） | 强制使用终端粘贴快捷键，补充自动识别无法覆盖的情况。 |
| 只想保存文字，稍后自己粘贴 | 仅剪贴板 | 只写入电脑剪贴板，不模拟粘贴，也不触发自动回车。 |

**并非所有 Linux 平铺桌面都支持自动识别**：当前实现了 Hyprland 和 Sway 的窗口查询；Windows 的识别也依赖常见终端名单与窗口特征。例如，编辑器内嵌终端的窗口可能仍被识别为编辑器，此时可手动选择「终端模式」。

「终端模式」只改变粘贴快捷键，仍然是直接向当前输入位置上屏，不需要额外连接。发送到普通应用时切回「直接上屏」。如果你自定义过终端的粘贴快捷键，需让它与对应模式的快捷键一致，或使用「仅剪贴板」手动粘贴。

手机显示 **「已上屏」** 表示剪贴板写入与模拟粘贴操作已成功执行；仍需先将电脑焦点放在目标输入区域。显示 **「已存入剪贴板」** 时，可手动粘贴；自动按键不可用会显示原因。开启「自动回车」后，仅在模拟粘贴成功时发送回车。

### 进阶使用：开机静默后台常驻

当你觉得好用、想每天随开随用时：
- **Linux**：在 `./menu.sh` 中用 **↑ / ↓** 选择「开启开机自启」，按 **Enter** 注册为 Systemd 用户服务；
- **Windows**：在 `menu.bat` 中用 **↑ / ↓** 选择「切换开机自启」，按 **Enter**，一键开启用户级静默自启（免管理员权限，开机自动通过 `pythonw.exe` 启动，无任何黑框窗口）。从此电脑开机自动在后台静默常驻，手机随时随地连入打字。

## 🔬 技术实现与进阶说明

### 1. 系统要求与桌面环境兼容性
- **支持平台**：
  - **Windows**：Windows 10 / 11（**无需安装任何额外依赖**，纯 Python 标准库开箱即用）
  - **Linux**：Linux Wayland（**GNOME**、**Hyprland**、**Sway** 等桌面）
- **Python 版本**：Python 3.8+（主服务使用标准库；GNOME 自动按键可选依赖系统 `python3-dbus`，无需 pip）
- **系统依赖说明**：
  - **Windows**：直接使用系统内置 Win32 API (`ctypes`)，0 额外安装项；可选安装 `qrcode`（`pip install qrcode`）以在终端中渲染二维码；
  - **Linux**：使用 `wl-clipboard`（剪贴板）、`wtype`（wlroots 按键模拟）、`libnotify`（通知）、`qrencode`（二维码）。GNOME 使用系统 `python3-dbus` 调用 Mutter 键盘接口；Ubuntu / Debian 可运行 `sudo apt install python3-dbus`。

| 桌面环境类别 | 代表桌面 / 系统 | 自动打字上屏 | 剪贴板写入 | 说明与限制 |
| :--- | :--- | :---: | :---: | :--- |
| **Windows 10 / 11** | 微信、记事本、浏览器、Windows Terminal、SSH 等 | ✅ 支持 | ✅ 支持 | 原生双通道支持，纯 Python 标准库驱动，终端/SSH 自动模拟 `Ctrl+Shift+V`，普通软件自动模拟 `Ctrl+V`，免装第三方包。 |
| **wlroots 平铺桌面** | Hyprland, Sway, Wayfire | ✅ 支持 | ✅ 支持 | Hyprland / Sway 支持常见终端自动识别；Wayfire 等未实现窗口查询的桌面，向终端输入时选择「终端模式」。按键模拟仍依赖合成器支持。 |
| **GNOME (Wayland)** | Ubuntu, Fedora 默认桌面 | ✅ 支持，需 python3-dbus | ✅ 支持 | 通过 Mutter 键盘接口模拟粘贴；终端请选择手机端「终端模式」。该接口为 GNOME 私有接口，若版本不兼容会提示手动粘贴。 |
| **KDE Plasma (Wayland)** | Kubuntu, openSUSE | ⚠️ 部分支持 | ✅ 支持 | 支持度取决于 KDE 版本对虚拟键盘协议的支持情况，部分场景按键可能响应不及时。 |
| **传统 X11 桌面** | XFCE, MATE, Cinnamon 等 | ❌ 暂不支持 | ❌ 暂不支持 | 核心依赖基于 Wayland 原生协议。若需在 X11 下使用，需手动将底层调用替换为 `xclip` 与 `xdotool`。欢迎社区 PR。 |
### 2. 双通道无损上屏策略 (Dual-Channel Strategy)

为什么不直接模拟敲字，而采用“剪贴板 + 模拟粘贴”？
- **直接击键模拟缺陷**：直接模拟输入中文容易遇到 Unicode 编码截断、打字速度缓慢以及与宿主机输入法候选词冲突的问题。
- **双通道方案优势**：
  1. **无条件写入剪贴板**：收到请求后 20ms 内写入系统剪贴板（Linux 原生 `wl-copy`，Windows 原生 Win32 API），保障数据物理不丢失；
  2. **智能自适应按键触发**：Hyprland、Sway 和 Windows 支持识别常见终端，终端模拟 `Ctrl+Shift+V`，普通应用模拟 `Ctrl+V`。GNOME 或未识别的终端可手动选择「终端模式」，详见上方模式说明；
  3. **手机端清晰状态反馈**：手机端分别显示“已上屏”或“已存入剪贴板”；按键失败时提示手动粘贴，不再把仅复制误报为上屏；
  4. **非阻塞清脆按键音反馈**：文字处理完毕后，异步播放一声轻快的客制化机械轴回车微敲击音（`pop.wav`），提供盲打听觉确认。

### 3. 音效自定义与切换指引 🎵

项目默认采用 **Tealios V2 客制化机械轴大键位 Enter 音**（`pop.wav`），非常清脆利落。

如果你喜欢其他敲击风格，项目在 `sounds_preview/` 目录下备选了多款不同质感的音频：
- **`1_清脆点击_windows_click.wav`**：经典极简清脆（Windows 官方导航点击声，极短极脆）；
- **`2_极简敲击_minimal_enter.wav`**：微型机械清响（来自 Mechvibes Minimal 调教）；
- **`3_真实机械轴_cream_enter.wav`**：高级机械轴实录（NovelKeys Cream 沉闷带脆）；
- **`4_客制化轴_tealios_enter.wav`**：顶级客制化机械轴 Enter 键实录（当前默认）。

**如何切换音效？**
只需将你喜欢的 `.wav` 音频文件**直接复制并重命名覆盖项目根目录下的 `pop.wav`**，重启服务后即可立即生效！
（若想完全静音，也可在启动时加上 `--no-sound` 参数）。

### 4. 移动端高保真交互设计

- **底部吸附底栏（Docked Footer）**：控制按钮紧贴大拇指黄金操作区，避免手机软键盘弹起时视口遮挡。
- **软键盘焦点保活（Focus Retention）**：发送按钮阻止按下时失焦，并在抬起时明确发送，兼容移动端浏览器；开关保留原生点击行为。
- **智能偏好持久化（Preferences Persistence）**：支持独立开启“自动清空”与“自动回车”，偏好自动保存在手机本地 `localStorage`，无需每次重复设置。
- **深浅双主题系统**：遵循 Apple / Linear 级 Design Tokens，支持右上角一键切换主题并持久化在本地。
- **本地历史记录**：所有记录保存在手机浏览器的 `localStorage` 中，支持统计字数、时间、单条一键重发与清空。

### 5. 命令行参数与自定义配置

直接运行后端核心脚本时支持的参数：

```bash
python3 voice_input.py [选项]
```

| 参数 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `--port` | `58002` | 服务监听端口（若被占用会自动切至备用端口 `53317`） |
| `--host` | `0.0.0.0` | 监听的主机地址（`0.0.0.0` 允许局域网外部设备访问） |
| `--display-ip` | 自动探测 | 终端二维码与首选展示的 IP 地址（支持环境变量 `VOICE_DISPLAY_IP`） |
| `--sound` / `--no-sound` | 启用 | 控制电脑端文字上屏成功时的轻微清脆提示音 |

## ❓ 常见问题 (FAQ)

<details>
<summary><b>Q: 手机必须要和电脑在同一个 Wi-Fi 吗？不在家能用吗？</b></summary>
<b>可以！</b> 本项目原生兼容任何异地虚拟组网工具（如 Tailscale、节点小宝、蒲公英等）。只要手机和电脑处于同一虚拟局域网，手机直接访问电脑在虚拟网络中的 IP 即可无缝输入。
</details>

<details>
<summary><b>Q: 会不会记录或泄露我说的内容？</b></summary>
<b>绝对不会。</b> 整个通信全部运行在你自己的私有局域网或点对点组网内，没有第三方服务器中转。电脑端内存即用即弃，不写任何磁盘日志；历史记录仅保存在你自己的手机浏览器本地。
</details>

<details>
<summary><b>Q: 在 GNOME、KDE 或传统 X11 桌面下能正常用吗？</b></summary>
<b>目前存在已知限制：</b>
<ul>
  <li><b>GNOME (Wayland)</b>：使用系统 <code>python3-dbus</code> 和 Mutter 键盘接口自动粘贴，无需 <code>wtype</code> 协议支持。终端请选择手机页面「终端模式」；依赖缺失或接口不可用时，文字保留在剪贴板，手机会提示手动粘贴。</li>
  <li><b>传统 X11 桌面</b>：当前版本完全面向现代 Wayland 协议设计。X11 下缺少 <code>wl-copy</code> 与 <code>wtype</code> 命令，暂无法直接开箱即用。</li>
</ul>
后续计划引入通用的 <code>ydotool</code> 或 X11 降级分流方案，也非常欢迎有对应桌面环境的用户提交 Issue 或 PR 协助适配！
</details>
